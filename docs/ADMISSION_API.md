# Versioned read-only admission hooks (development)

Compile against `com.github.gerolndnr.connectionguard.api.v1`, provided by the running guard, with compile-only dependencies. Never shade a duplicate core/native API. Only operator-trusted addons may register: this is an in-process extension API, not a sandbox or source of account identity proof.

`ConnectionGuardApi.registerAdmissionHook(id, hook)` returns an exact closeable registration. IDs are unique `[a-z][a-z0-9-]{0,31}`, eight registered maximum, four explicitly selected maximum. Registration alone is inactive; configure `integrations.admission.enabled/ids/failure-policy` and reload after startup. Selection captures actual handles; missing/closed/replaced registrations stay UNKNOWN until deliberate reload. An old handle cannot remove a replacement.

`AdmissionRequest` contains a normalized literal IP, platform, remaining monotonic caller budget and optional current verified UUID/provenance. Declared FORWARDED/global online flags/offline names alone supply no verified UUID. Platform adapters capture and recheck current native identity through their existing validated connection contract. Addons must not promote a name/claimed UUID or introduce blocking main-thread work.

Return a non-null `CompletableFuture<AdmissionResponse>`: `clear()`, `activeBan(expiryEpochMillis)` (zero for a native permanent ban), or `unknown(reason)`. Completion must represent completion of native work. Late completion cannot amend a finished login. Core never cancels native work on caller expiry and limits outstanding callback futures to 32 across unregister/replacement/shutdown; no new worker pool. A reload refuses while native futures remain outstanding. This is a bound on trusted callback futures, not proof that arbitrary third-party internals stopped physical database work.

Native checks occur before permission factories, normal provider/cache lookups and overload admission. Manual DENY retains first precedence; known ALLOW/exemptions cannot skip selected checks. CLEAR only continues ordinary policy. ENFORCE DENY or CLOSED+UNKNOWN stops early; if that early stopping fact becomes unavailable/expired before final projection, the login stays temporarily refused because ordinary checks have not run. It never turns into an unchecked OPEN admission. OPEN+UNKNOWN normally continues ordinary policy. OBSERVE continues normal evidence while suppressing the guard's own refusal; other plugins independently enforce their decisions.

`DecisionObservation.getAdmissionChecks()` is an immutable bounded separate list with source ID, typed response/reason/expiry and duration. Native facts are not VPN votes, detector-cache entries, automatic punishments or grants. `EXTERNAL_POLICY`/`EXTERNAL_UNAVAILABLE` reasons and flag explicitly separate these decisions; unavailable admission facts remain UNKNOWN_ALLOWED if ordinary OPEN checks complete without a flag. No extra lookup is caused by observation.

The optional [LibertyBans addon](../adapters/libertybans/README.md) is separately licensed and packaged. Challenge routing/completion, conditional rule-specific verified temporary grants, pure full policy replay/shadow and final feature release remain distinct unfinished requirements. The synthetic core tests alone are not installed SDK or authenticated-account qualification.
