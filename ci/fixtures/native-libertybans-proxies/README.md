# Native LibertyBans proxy qualification (development)

These fixture sources are AGPL-3.0-or-later; [license](../../../adapters/libertybans/LICENSE). Never install the fixtures on production. They create only finite synthetic bans in isolated owned native HSQL databases. The production [optional addon](../../../adapters/libertybans/README.md) remains read-only and separately packaged; no native SDK or addon classes enter the MIT combined JAR.

Four sequential owned loopback proxies on Java21, each limited to 256MiB: Velocity3.4.0/build566 (SHAfb599cbda6a6d01decce5e281f71f51cae7cacffcfafca32a09601f407b0583e) and BungeeCord26.1-R0.1-SNAPSHOT/build2100 (SHA8b9f75994fa6bd027e98827b3f83523f462c9e4b978fdab2fad00182ba4c924b), each with and without actual LibertyBans1.1.4 (SHA57303df011ff49747856af4ed818546f19b5dd84b8c627a6666431d0df962634). All backend targets were owned ports bound without listening until proxy shutdown. No backend was started or contacted successfully. bStats was disabled; ordinary sessions use synthetic offline identities.

The unchanged main developmental JAR is SHA477228bdba4e54a0c3ba82d118d8bf0cb68fed682c68a8cc82062eb9c51e286c; separate addon SHA9ca8005f41e64c946f50e6f8170e92ffce7f5ee1e753c61533856a6ae3a1bd60. Stable0.4.11 is unchanged and does not contain this new feature. These sources/receipts extend the [earlier actual Paper/Folia qualification](../native-libertybans/README.md).

Each installed-native fixture uses the **actual registered, selected addon hook** for seven native public-API cases: clear, active IP ban, exact UUID ban, foreign scope, expired, mute and revoked. Direct UUID input carries synthetic contract provenance; it does not prove authentication, genuine account ownership or a real forwarded player. Three separately labelled synthetic core-pipeline calls on the actual installed native hook verify early refusal, refusal despite a known exemption, and OBSERVE continuing provider work. They are not actual client logins or account proofs.

The 24 actual offline proxy login attempts produce 21 actual guard observations and three prior native refusals without guard capture. Six login-success packets were received; **none is a backend join**. Native bans remain effective with an ALLOW rule and OBSERVE. Clear still allows the ordinary VPN detector to refuse, and revoked bans permit ordinary checks again. Cancelling the guard runtime under CLOSED refuses without more provider work. Both missing-native fixtures compile and run without native SDK classes or a stand-in native provider: CLOSED refuses, OPEN still runs ordinary VPN detection, an OPEN negative retains UNKNOWN_ALLOWED, disabling selection restores ordinary checks, and CLOSED still refuses after cancellation.

There is a verified platform ordering difference. On selected Velocity, native LibertyBans refuses before the guard's LoginEvent handler; the guard preserves the prior refusal and emits no own observation. On selected Bungee, the guard hook sees the ban and can stop provider work; its OBSERVE observation can say ALLOW while the native plugin still refuses. A guard observation never claims final admission by other plugins. Native enforcement was not disabled to make these tests pass.

To reproduce on an authorized local host: build `./gradlew check shadowJar :adapters:libertybans:jar` and verify both archives. Pin actual runtime/native JARs to the above hashes. Compile `BanFixtureCore.java`, the matching platform wrapper and (only for installed-native variants) `NativeBanSupport.java` with `javac --release 21 -proc:none` against the developmental guard/addon, actual proxy and, only where installed, native SDK. Package only the resulting `fixture/*.class`, matching `velocity-*.json` as `velocity-plugin.json` or `bungee-*.yml` as `bungee.yml`, and the AGPL notice. Missing variants must exclude NativeBanSupport and the native SDK from compile and runtime paths.

Use a fresh private directory, reserve every backend target, disable bStats, load the [native fixture configuration](../native-libertybans/native-config.yml) with OFFLINE synthetic UUID resolution, and explicitly select provider `native-ban-fixture`, observer `native-ban-observer` and admission `libertybans`. Reload after addon startup. The root operational driver `tools/release_native_ban_proxy_test.py` accepts `--platform velocity|bungee`, `--fixture <fresh-name>`, explicit `--artifact/--sha256` and `--addon/--addon-sha256`, plus `--without-native` for actual absence. It compiles only the matching source set, sends the finite prepare/probe/pipeline/provider commands, performs protocol760 loopback logins, checks exact typed observations/provider counts, and always stops its owned process. Native scope/expiry/UUID input remains distinct from normal offline login authority. Source and private final log hashes are in the four public JSON receipts.

Failed attempts are retained in [failed-attempts-2026-10-03.json](failed-attempts-2026-10-03.json): a wrong expected guard capture on Velocity, a fixture-only invalid Bungee enum (no runtime), and an incorrect assumption that Bungee shared Velocity's native order. Only test expectations/source were corrected; production code, strict configuration and native enforcement were unchanged.

This is not qualification of authenticated Mojang/Xbox accounts, actual native historical-alt associations, other runtime/native versions or forks, atomic database admission during concurrent ban changes, challenge routing/completion, conditional verified grants or the full compatibility matrix. All five complete differentiators and the separate feature release remain outstanding.
