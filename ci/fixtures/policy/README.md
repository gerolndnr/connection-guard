# Owned policy/replay qualification

The shared fixture registers a synthetic Provider SPI source and observer, and an owned loopback geo source. The three wrappers bind actual Velocity, BungeeCord and Paper/Folia commands/events. They contain no server API or plugin copies. Never install them on a public server.

`examples.json` is the same eight-case synthetic dataset bundled with the plugin. `candidate.json` is a complete policy draft; it is not activated by `/cg policy test`. Real provider accuracy, real account authentication, full admission/identity replay and production telemetry are outside this scope.

The operational harness checks nine policy/replay cases on each pinned runtime: offline replay without source calls/actions, comparison without activation, positive VPN refusal/flag command, OBSERVE allowance, geo blacklist refusal, whitelist allowance, empty whitelist refusal, invalid reload retention and a literal DENY added while geo is pending after permission exemption. The new shadow scope adds six cases: the live refusal remains effective when the candidate allows, stop freezes new sampling, candidate refusal cannot kick an actual allowed player, invalid reload retains the active comparison, valid reload ends it, and a changed geo provider ends it. Successful shadow logins require exactly one provider call, action counts corresponding only to the active policy, and one actual decision observation. Backend allowed cases require an actual synthetic PlayerJoinEvent; proxy-only success is not called a backend join. Planned cases are only proved by a successful hash-bound receipt.

Local qualification uses sequential loopback-only Paper 1.21.11 build 132/Folia 1.21.11 build 14 servers, at most 768 MiB, with explicit EULA authorization; Velocity 3.4.0 build 566 and BungeeCord 26.1 build 2100 proxies. Cloud and bStats are disabled. Retained receipts bind JAR/runtime/addon/source/driver/log hashes. The operational driver and environment dependencies currently live in the ownership workspace; a portable public benchmark harness remains separate work.

The four `runtime-*.json` receipts now record 15 successful cases each against source `f9c2827` and main JAR `68e02df6e8cb57b5267383a1f2b055edfad7496af7d925b48068d355893fe9c0`: 44 actual decision observations and eight synthetic Paper/Folia join events. All owned runtimes stopped cleanly. `driver.py` is the exact operational driver used; it requires the existing ownership workspace helpers on `PYTHONPATH`, pinned runtimes, and explicit backend EULA authorization. Their environment is not a portable public test distribution. Original console logs are retained privately; receipts contain hashes and bounded counters without raw addresses/identities. These results do not qualify other builds, production accounts, provider accuracy, competitor rates or latency budgets.
